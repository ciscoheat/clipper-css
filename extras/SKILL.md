# Convert A Website To Clipper

Recreate supplied web content in Astro or SvelteKit with Clipper. The source evidence defines the result; Clipper supplies the layout and token system. Do not invent copy, imagery, controls, sections, or visual treatment.

## Workflow

Work in this order: **bands, flow, skeleton, metrics, color, integrity, verify**. Do not advance until each step's completion check passes. The source controls the result; Clipper supplies the simplest structure that expresses it. After every substantive edit, run one focused check before reading or editing another slice. Never treat a successful build as visual verification.

1. **Bands.** Inspect every supplied viewport; capture desktop and mobile screenshots for a live page. Read the target route, layout, `variables.css`, `components.css`, and `clipper.css`. Divide the page top to bottom into visible horizontal bands: header, hero, content sections, footer, and any separator or full-bleed region. Treat shared-layout landmarks as bands too: `header` and `footer` must each get their own row in the band map even when their markup lives outside the route. For each band, record its vertical start and end, height, full-bleed or bounded edges, space before the next band, background color or image, foreground color, border, transparency, and a visual appearance label such as bright, dark, tinted, transparent, or image-backed. The appearance label is evidence from the screenshot, not an inference from the CSS value. **Done when** every visible pixel row belongs to one ordered band and the map has explicit header and footer color and appearance entries.

2. **Flow.** Parse each band independently from top to bottom. Record its direct content units: heading group, copy, image, control, horizontal peer group, repeated items, or nested full-bleed module. Mark each unit as vertical flow, horizontal row, or multi-column grid. A group is a grid only when source peers occupy explicit columns; record its desktop columns and the supplied viewport where it collapses. For live pages, audit the DOM and rendered boxes so image-only links, SVGs, CSS backgrounds, below-the-fold items, and empty-label controls remain in the inventory. Record every item's copy, destination, media, source order, and count. **Done when** every band has an ordered list of units and every source item is accounted for.

3. **Skeleton.** Write the smallest semantic markup that matches the band and flow map: `header`, `main`, direct child `section` bands, and `footer` only when present. A section's ordinary content stays direct. Add one wrapper only for a mapped row, grid, overlay, or bounded module. Let Clipper's default column flex flow express vertical units; add `row` for horizontal peers and explicit grid columns for mapped multi-column groups, with evidence-supported mobile collapse. Use real headings, links, buttons, inputs, lists, and images. Use `full-width` for a full-bleed hero or band, with `page-width` on bounded inner content. Express all route styling with static Tailwind and Clipper classes: do not add route-level CSS, `<style>` blocks, style attributes, or page-specific stylesheets. **Done when** the route mirrors the map without invented wrappers, cards, sections, missing items, or custom route CSS.

4. **Metrics.** Match geometry before decoration. Set `--max-page-width` from the largest source viewport. Match band heights, content edges, grid tracks, peer widths, gaps, padding, image crops, and responsive states with static Tailwind and Clipper classes. Size equal peers with shared tracks or `w-full`; use `min-w-0` where text must shrink. Map each text role's family, weight, size, line height, letter spacing, alignment, and container edges. Text fills its mapped, fluent Clipper container: use the section column, `page-width`, `readable`, `w-full`, or responsive grid tracks as the map requires. Converted route markup must contain no `max-w-*` classes. Load the exact or closest Google Font in the HTML header and set the fluid scale in `variables.css`. **Done when** screenshots match in silhouette, alignment, and wrapping before color comparison, with no `max-w-*` class in the route.

5. **Color.** Extract and tokenise every band background, surface, foreground, border, outline, and focus color in `variables.css`; each source-visible band has an intentional background token. This includes the shared `header` and `footer`, which must never rely on `body`, `--background`, or browser defaults unless the source was measured to use exactly that value. Record image, gradient, transparency, and animation treatments separately from fallback colors. Preserve the source screenshot’s visual appearance label as an independent acceptance criterion: a computed translucent white header must still render as a bright band, and a numerically close color that looks dim, tinted, or dark fails the check. Apply visual treatment with Tailwind and Clipper utilities; shared generic contracts belong in `components.css`. A dynamic `background-image` attribute is permitted only when the source requires a runtime image URL that classes cannot express. **Done when** the color matrix has a measured source value, appearance label, and explicit target declaration for every band, including header and footer, with no visible color or type role falling back on an unmeasured starter or inherited value.

6. **Integrity.** Before trusting a screenshot, inspect the edited diff and the rendered DOM. Confirm every edited shared stylesheet still has one valid declaration for each token, the Astro frontmatter has intact `---` fences, and each required landmark occurs exactly once (`header`, `main`, `footer`, and mapped direct-child sections). Check that no old starter markup remains beside the replacement. In the browser, assert the header and footer have non-zero boxes and explicit computed backgrounds, the hero has non-zero height, visible text has a non-transparent computed foreground color, controls have readable foreground/background contrast, and the document has no horizontal overflow. For each mapped band, inspect `getComputedStyle(band).backgroundColor`, `backgroundImage`, `color`, and `borderColor`; compare header and footer values against their source captures rather than against one another or against the body. Then compare the source and target screenshots at identical viewport dimensions at normal zoom, checking the recorded appearance label for every band. A band with an unexpected inherited or transparent background, or a computed value that passes while the screenshot visibly has the wrong brightness or tint, is a failed integrity check. Capture a screenshot at the largest and smallest supplied viewports. **Done when** the diff is structurally clean, the landmarks are unique, all key boxes are non-zero, each band’s computed color and screenshot appearance match its matrix entry, text is visibly legible, and the screenshot is inspectable at normal zoom.

7. **Verify.** Compare every supplied viewport and each mapped breakpoint boundary: first bands and geometry, then copy, media, controls, borders, type, colors, and peer alignment. Inspect computed background, foreground, border, `font-family`, `font-size`, `font-weight`, `line-height`, and `letter-spacing`; verify repeated item count, order, destinations, and media against the source. Check focus, overflow, and text wrapping, especially centered text blocks. Audit the route for `max-w-*`, `<style>`, style attributes, and page-specific stylesheet imports; `max-w-*` is a conversion failure, so restore the text to its fluent section, page-width, readable, `w-full`, or responsive grid container. Move shared decisions to `variables.css` or `components.css` and express all route decisions as Tailwind or Clipper classes. Rework the earliest failing map stage, then rerun the comparison. **Done when** the rendered result matches every map entry at the largest and smallest supplied viewports, the route contains no `max-w-*` or custom CSS, the integrity checks pass, and the project build passes.

## Edit And Screenshot Safety

- Apply one file or one tightly related slice at a time. If an edit tool reports a corrected or partial patch, stop and inspect the full file and `git diff` before continuing; do not assume the intended replacement happened.
- After editing a shared stylesheet or layout, run the narrowest available build/type check immediately. Then reload the local route and inspect computed styles before changing route markup.
- Treat any screenshot with faint, missing, duplicated, or overlapping content as a failed conversion even when the build passes. Diagnose CSS tokens, duplicate landmarks, stacking, opacity, and zero-sized boxes before adjusting copy or spacing.
- Use a browser assertion like `getComputedStyle(element).color`, `getComputedStyle(element).backgroundColor`, `getComputedStyle(element).backgroundImage`, `getComputedStyle(element).borderColor`, `element.getBoundingClientRect()`, and `document.documentElement.scrollWidth <= document.documentElement.clientWidth` for every visible band. Always include separate assertions for `header`, the hero, primary heading, primary CTA, and `footer`; do not infer header/footer colors from `body` or from a shared token without checking the rendered elements.
- Before editing, capture the source computed background values for `header` and `footer` at the largest and smallest supplied viewports. After editing, run the same assertions against the local route and fail the conversion when either band differs without an intentional, documented source reason.
- Place the source and target captures beside each other at the same viewport dimensions and inspect them at normal zoom. Explicitly answer for every band: does it read as bright, dark, tinted, transparent, or image-backed in both captures? Do not mark the color stage complete from computed values alone.
- Do not report completion from a single viewport or from a screenshot viewed only at a zoomed-out full-page scale. Inspect the first viewport at desktop and mobile sizes, plus a full-page capture for band order and missing content.

## Clipper Quick Reference

- `section` is a page-width grid band with fluid block padding and vertical gap.
- Direct children of `section`, `header`, and `footer` occupy the center page column.
- `div`, `nav`, `ul`, and similar containers default to vertical flex layout with a gap.
- `row` creates a horizontal flex group; `grid` and explicit `*-cols-*` classes create a grid.
- `full-width` breaks a direct child out of the page column; place `page-width` on its inner content when needed.
- Fluid tokens such as `gap-lg`, `py-xl`, and `mt-4xl` provide the default rhythm. Use static utilities only when the geometry map needs a specific exception.
